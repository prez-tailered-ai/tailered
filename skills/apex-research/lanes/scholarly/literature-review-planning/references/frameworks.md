# Question frameworks

The framework decides what counts as a sub-area. A wrong one sends searches to tangential papers.

| Framework | Fits | Components |
|---|---|---|
| Population-intervention-comparison-outcome (default) | most clinical and quantitative questions | population, intervention, comparison, outcome |
| Sample-phenomenon-design-evaluation-research type | qualitative, experiential, mixed methods | sample, phenomenon of interest, design, evaluation, research type |
| Decomposition | systems, methods, engineering | problem, solution, evaluation, limitations |
| Hybrid | questions that truly span the above | components drawn from more than one, each labelled with its origin |

## Signals

- "compared with", "versus", a treatment or drug: the default framework.
- "experience", "perception", "meaning", interviews, ethnography: the qualitative framework.
- a system, model, algorithm, benchmark or metric: decomposition.
- strong signals from two families: hybrid.
- no signal: the default.

State the pick with its confidence and which signals fired. If the user insists on a framework the signals contradict, push back once, then follow the user.

## Rules

- Map each component to one sub-area, then add one cross-cutting sub-area.
- If three of five components do not map naturally, the framework is wrong; restart rather than force it.
- Use hybrid only when a single framework fails at the checkpoint; it produces fuzzier sub-areas.
