# Whole widget check

Jobs made hardware, software and services one product: he ended Mac clone licensing in 1997, then paired the iPod with iTunes (2001, store 2003). The company's capture, model, day build and main product are separate parts, but a member sees one product. The guard: iTunes songs were tied to Apple devices by copy protection until 2009. One product must not trap the member: every book's and market's price stays visible.

## When to Activate

- One member path crosses several surfaces.
- The owner says "one product", "the pieces don't match" or "the whole widget".
- Before a feature touching more than one surface goes out.

Do not use for:
- finding which layer made one wrong number: tailered-ai:full-stack-trace;
- own or buy after a supplier failed: tailered-ai:stoppage-to-ownership;
- merging league scripts: tailered-ai:one-chassis-audit.

## Inputs and outputs

Where to work: create a task folder, `artifacts/<skill name>-<YYYYMMDD>/` in the current project (this session's scratchpad if the project is read-only), and write the output there. Tables go in your reply.

Inputs: the member path, the surfaces it touches, and a game to walk it on.

Missing inputs never leave a blank. Put in a concrete proposal from what you know, mark it `proposal`, finish every step, and end with the one or two inputs that would change the result. A proposal is a real value: a dollar figure, a name, a date, a game, a list of likely items. Writing missing, pending, unknown, TBD or $X in its place is still a blank. When you cannot open the page, file or data a step asks for, still fill every row: name the exact page, file or command to check and the value you expect there, marked `proposal`. Every row of every table gets a verdict word and an owner.

Output: `path.md`: the path, the seam table, owners, the trap check and the verdict.

## Steps

Lead the reply with the seam table: one row per seam on the named path, comparing number, rounding, name, time and marks, with the value seen on each side or the value expected, marked proposal; each mismatch gets an owner and a starting layer; then keep, change or stop for the path.

Lead the reply with the seam table, then the verdict line, then detail.

### 1. Walk the path

Pick one path and one real game, such as tonight's first NBA game from main product card to dashboard to the partner source link. List each screen in order with its owner.

Completion: a numbered list of steps, each with a surface and owner.

### 2. Check the seams

At each hand-off compare the number and its rounding, the name, the time and time zone, and the team and league marks. Write the values seen.

Completion: a table of seams, each match or mismatch with the values seen.

### 3. Give each mismatch an owner

Name one owner for the whole path. Give each mismatch a fix owner, the layer it starts in, and a date. Word changes go through tailered-ai:design-craft. Verdict for the path: keep (no mismatch), change (named fixes) or stop (the path misleads a member).

Completion: every mismatch has an owner and date, and the path has a verdict word.

### 4. Check it does not trap

At each step, can the member see every book's and market's price, not only ones the company favors, and leave to any of them? Fixes ship through tailered-ai:workflow and the release coordinator on the owner's word.

Completion: a yes or no per step, and the release route named.

## Anti-Patterns

- Checking each surface alone and never the hand-offs.
- Fixing a mismatch on the card when it starts upstream.
- A path with no single owner.
- Hiding a rival's price to keep members in.
